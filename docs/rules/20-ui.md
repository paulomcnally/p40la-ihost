# 20 — UI y componentes

> **Dominio**: componentes obligatorios, tokens de tema, patrones de listado, i18n y guardrails de UI.
> **Cargar cuando**: la spec toca frontend, formularios, listados, selectores, modales o componentes.

---

## UI-SELECT — Selector obligatorio: componente `Select`

- **Todo** selector de opciones (color, mes, moneda, estado, institución, país, categoría, etc.) DEBE usar `frontend/src/components/Select.tsx`.
- **Prohibido** `<select>`/`<option>` nativo: muestra el dropdown del sistema operativo y rompe el patrón visual.
- Los selectores con muchas opciones DEBEN ser `searchable`: buscador con autofocus, filtrado por etiqueta sin distinguir mayúsculas ni acentos.
- El componente usa portal, tokens de tema y `z-[90]`.

**Guardrail**: `check:ui` (regla `UI-SELECT`) → `cd frontend && npm run check:ui` (el build también falla si aparece un `<select>`).
**Precedentes**: SPEC-004 CA-022, SPEC-111 CA-018, SPEC-118.

---

## UI-SELECT-ADD — La opción de agregar dentro de un dropdown se rotula «Agregar»

- Toda opción de un `Select` que **crea o agrega una entidad** (institución, agente, persona, categoría, etc.) DEBE rotularse con la clave genérica `app.add` («Agregar» / «Add») y mostrar el ícono `plus` antes del texto.
- **Prohibido** usar en la opción etiquetas largas o específicas: «Agregar inmobiliaria», «Nueva categoría», «Nueva persona».
- El **título del modal o formulario** que se abre sí puede ser específico («Agregar inmobiliaria», «Nueva categoría»).
- Usar `addOption(label, value)` de `frontend/src/components/Select.tsx` para que el ícono y el valor centinela sean consistentes.
- La opción se ubica al final de la lista.

**Precedente**: SPEC-140.

---

## UI-INPUT-TOKENS — Inputs con tokens del tema

- Todo `input`, `select` y `textarea` DEBE usar `bg-card` como fondo y `text-text` / `text-text-secondary` para texto y placeholder.
- **Prohibido**: `bg-white`, `dark:bg-[#2c2c2e]`, `text-black` o cualquier color hardcodeado.
- El color global de los form controls lo fija `frontend/src/index.css`; no duplicarlo por formulario.

---

## UI-DARKMODE — Verificación en darkmode

- Todo formulario, modal o componente nuevo DEBE verificarse en darkmode antes de considerarse completo: texto y placeholders legibles.
- Si se omite, la spec no pasa a `pending_release`.

**Precedente**: SPEC-060.

---

## UI-TOGGLE — Booleanos con `Toggle` iOS

- Todo booleano de entidad o configuración (`active`, `enabled`, `auto_generate`, `is_recurring`, `required`, etc.) DEBE usar `frontend/src/components/Toggle.tsx`.
- **Prohibido** `<input type="checkbox">` para estos casos.
- Excepción: checkboxes de selección múltiple de filas o items, que no representan un estado persistido de la entidad.
- El toggle debe tener etiqueta visible o `aria-label`, foco visible por teclado y verificarse en darkmode.

**Precedente**: SPEC-135.

---

## UI-LIST-PATTERN — Patrón de páginas de listado

- Los listados usan **cards** con menú de acciones de 3 puntos.
- Si no hay registros: `EmptyCard` con título, descripción y botón de acción.
- **Prohibido** poner formularios inline dentro de un listado.
- Referencia de implementación: `frontend/src/pages/HomesPage.tsx`.

**Precedente**: SPEC-017, SPEC-022.

---

## UI-CREATE-MENU — Acción de crear en el header

- Toda página con acción de crear usa `CreateMenu` (ícono de 3 puntos verticales) en el header, desde `frontend/src/components/CreateMenu.tsx`.
- **Prohibido** botones directos «Crear» o «+» en el header.

---

## UI-EDIT-LABEL — La acción de edición se rotula «Editar»

- Toda acción de edición se rotula **Editar**, sin importar la entidad ni la página: menús de 3 puntos, dropdowns, headers y botones usan la clave i18n genérica `app.edit` (`Editar` / `Edit`).
- **Prohibido** rotular acciones como «Editar servicio», «Editar deuda» o «Editar [página]».
- Los **títulos de formulario** sí pueden ser descriptivos (clave específica); la regla aplica solo a etiquetas de acciones.

**Precedente**: SPEC-114 usó `services.edit` en el menú; SPEC-115 lo corrigió a `app.edit`.

---

## UI-I18N — Fuente de verdad del i18n

- Las traducciones se editan **SIEMPRE** en `frontend/public/i18n/{es,en}.json`.
- **Nunca** editar `public/i18n/*.json` directamente: es salida del build y se sobrescribe.
- El build de Vite (`npm run build` en `frontend/`) usa `emptyOutDir: true` sobre `public/`.
- Después de editar i18n: correr `npm run build` y verificar con `curl -s http://localhost:8088/i18n/es.json` que las claves nuevas se sirvan.
- Toda clave usada con `t('...')` DEBE existir como **string** en `es.json` y `en.json`. **Prohibido** apuntar a un objeto padre (`t('rental.role')` en vez de `t('rental.role.tenant')`).
- Las claves deben existir en **ambos idiomas** (paridad es/en).
- Las claves dinámicas (``t(`rental.role.${role}`)``) deben tener un prefijo que exista como objeto en el diccionario.

**Guardrail**: `check:i18n` (regla `UI-I18N`) → `cd frontend && npm run check:i18n`. Corre en `npm run build` y en `.githooks/pre-commit`.

**Precedente**: SPEC-032/033 — claves editadas en `public/i18n/` desaparecieron en el build. SPEC-140 — `rental.reference` faltante y `rental.role` apuntando a un objeto.

---

## UI-STYLE — Estilo general

- Diseño inspirado en iOS: `rounded-ios`, `shadow-ios`, colores del sistema.
- Sidebar fijo a la izquierda; header sticky con título y acciones a la derecha.
- Cards con hover effect y menú de acciones que aparece al interactuar.
- Modales de confirmación para acciones destructivas.

---

## UI-GUARDRAIL — Cobertura del guardrail automático

- `frontend/scripts/check-ui-rules.cjs` detecta `<select>` nativo y `<input type="checkbox">` en archivos `.tsx`/`.jsx` (allowlist: `components/Toggle.tsx`). Se ejecuta en `npm run check:ui` y en el build.
- `.githooks/pre-commit` y el plugin `.opencode/plugins/rules-guard/` extienden la prevención a escrituras y commits, e incluyen `public/i18n/`.
- **No** cubren automáticamente: colores/tokens hardcodeados, implementación de modales, `app.edit`, `BACK_ROUTES`, patrón de listados ni darkmode. Esas reglas se verifican manualmente y se declaran en la spec.
